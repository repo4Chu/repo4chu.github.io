We'll use nmap to find ports and services running on the machine:

● shell
nmap -sS -Pn -A 10.10.11.111 -p 22,80

-sS: syn scan.
-Pn: já sabemos que o host está ativo então desativamos o discovery.
-A: Detecção de OS, detecção de versão, script scanning, and traceroute
-p: especifica as portas

We can see two open ports, 22(SSH) and 80(HTTP).

Accessing the site by IP, we get redirected to the forge.htb name, so we need to add forge.htb to the /etc/hosts file

Now that we can access the site, we can see a link to an upload page.

Accessing it, we have two upload options. We can upload files locally or via URL. I tried a bunch of things through the local upload but had no luck.

Trying to pass a local address through the URL, I noticed there was an active blacklist.

A simple bypass was to use uppercase characters, which got me past the blacklist.

With that, we get the link from the successful upload.

Using 'curl' we can see the contents of the file with the index.html, which means our SSRF flaw is validated.

Using ffuf to enumerate subdomains, we get an interesting result: admin.forge.htb

We add the new name to the /etc/hosts file.

Accessing the page http://admin.forge.htb, we get a message saying only local access is allowed.

Let's use the already-proven SSRF technique on the http://forge.htb/upload page to fetch the contents of http://admin.forge.htb

We can see the http://admin.forge.htb name is being blocked the same way as the attempt made using http://localhost

Let's use the same uppercase character technique to get a bypass for the admin page.

I used BurpSuite to make the response easier to read. With that, we can read the contents of the page http://admin.forge.htb, validating the SSRF bypass. We can see two pages besides index.html /annoucements /upload

Now let's pass the full path to the page we want, http://admin.forge.HTB/annoucements

In the response of our request, we can read the contents of the page http://admin.forge.htb/annoucements, and in it we can grab credentials for an internal FTP service. We can also see a message saying the upload page now supports other protocols, like FTP and FTPS. In the third message we have the announcement telling how to use the parameters.

We have an FTP server running internally, and we can interact with it through the page http://admin.forge.htb/upload using the FTP protocol, with the parameters described in the third point. Since both admin.forge.htb and localhost are on the blacklist, we need the uppercase character bypass on both. Our final query http://admin.forge.HTB/upload?u=ftp://user:heightofsecurity123!@LoCaLhOsT

With that, the response of our request gives us the FTP directory listing, in this case /home/user

We can get the link to our first flag by passing the full path of the file: http://admin.forge.HTB/upload?u=ftp://user:heightofsecurity123!@LoCaLhOsT/user.txt

With that, we get our first flag

I tried to log in via SSH using the FTP server credentials, but the authentication method is public key only.

So let's read the RSA key in the user's SSH directory. http://admin.forge.HTB/upload?u=ftp://user:heightofsecurity123!@LoCaLhOsT/.ssh/id_rsa

That gives us the user's private RSA key.

We write the key to a file

And we start the SSH connection using the key we got.
