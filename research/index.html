opencart 4.1.x — api route case confusion → unauthenticated account takeover

draft

~/research/opencart-api-case-confusion.md

route matching is case-sensitive at the auth guard and case-insensitive at the router. request /api/v1/users/PASSWORDRESET instead of the canonical path and the guard never fires. chain it with the password reset flow and you take over any user account with zero credentials — the admin panel is not in reach, the advisory is explicit about that. ghsa drafted, not filed yet; no vendor response on file.

  • vendor=opencart
  • product=4.1.x
  • --cvss=9.8
  • --cwe=178
  • --cwe=287
  • id=ghsa (draft)
